# UE
# UE 引用类型完全指南：硬引用 · 软引用 · TObjectPtr

## 一、概念总览

在 Unreal Engine 中，资源引用方式直接影响内存占用、加载性能和编辑器稳定性。主要分为三种类型：

| 类型 | 核心机制 | 对 GC（垃圾回收）的影响 | 加载时机 |
|------|----------|--------------------------|----------|
| **硬引用（Hard Reference）** | 通过原生指针（`UObject*`）或属性宏直接持有对象 | 阻止 GC 回收，对象常驻内存 | 引用对象所在资源被加载时一并加载 |
| **软引用（Soft Reference）** | 通过路径字符串（`TSoftObjectPtr`/`TSoftClassPtr`）间接指向资源 | 不阻止 GC，对象可随时被回收 | 仅在使用时显式异步加载 |
| **TObjectPtr** | 智能指针包装的硬引用（UE5+） | 与硬引用完全一致，阻止 GC | 同硬引用，加载时机完全一致 |

> 关键区别：**硬引用**和 **TObjectPtr** 都属于“持有型引用”，资源会长期驻留；**软引用**属于“非持有型引用”，资源按需动态加载。  
> **TObjectPtr 并不是软引用，它是硬引用的安全增强版。**

## 二、详细对比

| 对比维度 | 硬引用（原生指针） | TObjectPtr | 软引用（TSoftObjectPtr） |
|----------|-------------------|------------|--------------------------|
| **本质** | 普通 C++ 指针 | 智能指针（内部封装了指针和 GC 钩子） | 资产路径（FSoftObjectPath）+ 加载器 |
| **内存占用** | 8 字节（64位） | 8 字节（与原生指针相同） | 路径字符串（约几十字节） |
| **是否阻止 GC** | ✅ 是 | ✅ 是 | ❌ 否 |
| **访问速度** | 直接访问，极快 | 直接访问，几乎无额外开销 | 需先调用 `LoadSynchronous()` 或异步加载，有 I/O 延迟 |
| **空安全** | 手动检查（`IsValid()`） | 自动检查，访问空对象不会立即崩溃 | 需手动检查是否有效（`IsNull()` 或 `Get()`） |
| **编辑器支持** | 普通显示，无法追踪引用关系 | 完整支持引用查看器、重定向、跨模块追踪 | 支持，但加载状态需额外处理 |
| **跨模块稳定性** | 低，容易出现悬空引用 | 高，GC 后指针自动置空 | 高，因不持有对象，不会产生悬空 |
| **适用版本** | UE4 / UE5 全版本 | UE5 推荐，UE4 无此类型 | 全版本 |

## 三、各自详解

### 1. 硬引用（原生 UObject*）

**行为特点**  
- 在 `UPROPERTY` 中标记的指针会被引擎识别为资源依赖，打包时会将引用的资源一起打入包内。  
- 引用的对象在整个生命周期内都不会被 GC 回收，直到引用本身被释放。  
- 使用时无需额外加载操作，直接访问即可。

**优点**  
- 访问效率最高，无任何延迟。  
- 代码编写简单，无需处理异步逻辑。  
- 依赖关系明确，便于资源审计。

**缺点**  
- 即使资源暂时不用，也会一直占用内存，可能导致峰值过高。  
- 加载时所有依赖资源一次性载入，启动/切换关卡可能卡顿。

**适用场景**  
- 角色基础模型、动画蓝图、常用 UI 框架、游戏逻辑中必备的核心资源。  
- 需要频繁访问且无法容忍加载延迟的对象。

---

### 2. 软引用（TSoftObjectPtr / TSoftClassPtr）

**行为特点**  
- 仅存储资源的路径字符串，不持有对象实例。  
- 对象可以随时被 GC 回收，内存占用极低。  
- 使用前必须显式加载（同步或异步），加载完成后才能访问实际对象。

**优点**  
- 大幅降低常驻内存，内存紧张时可自动释放。  
- 按需加载，可减少初始加载时间。  
- 适合大型资源（如超大贴图、CG 视频、可选皮肤）。

**缺点**  
- 访问前必须加载，若未预加载则会产生明显的 I/O 卡顿。  
- 需要处理加载状态和失败情况，逻辑复杂度上升。  
- 同步加载（`LoadSynchronous()`）会阻塞主线程，应尽量避免。

**优化加载策略**  
- **预加载（Preload）**：在预期使用之前提前发起异步请求，使资源在真正使用时已经就绪。  
- **异步加载 + 过渡 UI**：在加载期间显示加载动画或提示，避免界面假死。  
- **分帧加载**：将资源分批异步加载，每帧处理一部分，将卡顿分散到多帧。  
- **对象池（Object Pool）**：对于高频复用对象，首次加载后永久缓存（转为硬引用），避免重复加载。

---

### 3. TObjectPtr（UE5 安全硬引用）

**行为特点**  
- 本质上仍是硬引用，持有对象并阻止 GC。  
- 内部集成了引擎的 `FGCObject` 机制，在对象被销毁时自动将指针置空，避免悬空访问。  
- 编辑器层面提供更完善的引用追踪和重定向支持。

**与原生硬引用的区别**  
- 原生指针在对象被 GC 销毁后，仍保留原地址，访问会导致崩溃；TObjectPtr 会自动变为 `nullptr`。  
- 在编辑器中移动/重命名资源时，TObjectPtr 的引用会自动更新（需配合 `UPROPERTY`）。  
- 跨模块（如插件之间）引用时更加安全，降低因加载顺序导致的不稳定。

**使用建议**  
- `UPROPERTY` 成员变量：优先使用 `TObjectPtr<T>`（UE5 官方推荐）。  
- 函数局部变量或临时指针：仍可用 `UObject*`，生命周期短，无需额外开销。  
- 容器（如 `TArray`）内存储：推荐使用 `TObjectPtr`，保证 GC 安全。  
- 函数参数：通常用 `UObject*` 即可，简单高效。

## 四、三者组合使用策略

在实际项目中，这三种引用并非互斥，而是各有分工：

| 场景类型 | 推荐引用方式 | 原因 |
|----------|-------------|------|
| **核心功能对象**（角色、武器、必备 UI） | `TObjectPtr`（或原生硬引用） | 必须常驻内存，不容许加载延迟 |
| **可选内容**（皮肤、DLC 包、额外特效） | `TSoftObjectPtr` + 预加载 | 节省内存，按需加载 |
| **临时缓存**（动态生成的 Actor 引用） | `TWeakObjectPtr`（弱引用）或 `TObjectPtr` | 若不想阻止销毁用弱引用，若需保证存活用 TObjectPtr |
| **编辑器工具代码** | `TObjectPtr` 更安全 | 避免编辑器中反复编译/卸载导致崩溃 |
| **高性能循环**（每帧大量访问） | 原生 `UObject*` | 减少智能指针额外检查（虽然开销极小，但数量极大时仍建议裸指针） |

## 五、常见误区纠正

| ❌ 错误认知 | ✅ 正确解释 |
|------------|------------|
| “TObjectPtr 是软引用，能省内存” | TObjectPtr 是硬引用，持有对象，不省内存。 |
| “用了软引用就一定不卡顿” | 软引用在加载时依然会产生 I/O 延迟，需配合预加载/异步策略。 |
| “所有指针都应改为 TObjectPtr” | 仅建议在成员变量上使用，局部/临时用裸指针更轻量。 |
| “TObjectPtr 比原生指针慢很多” | 实测性能开销极小（<1%），可忽略。 |
| “硬引用就是不好的，尽量少用” | 硬引用是性能基石，核心资源必须用。过度软引用会增加代码复杂度和加载不确定性。 |
